# 文风蒸馏 · Writing Style Distill

派生自 [女娲 · Skill造人术](https://github.com/alchaincyf/nuwa-skill)（`huashu-nuwa`），**只保留「表达层」**：不构建完整思维操作系统，专精于**句式、词汇、节奏、修辞与篇章习惯**，产出可被反复打磨的「写作声线 Skill」。

## 与女娲的差异

| 维度 | 女娲 `huashu-nuwa` | 本 Skill |
|------|-------------------|----------|
| 目标 | 心智模型 + 决策 + 表达 | **写作风格 + 表达方式 + 辅助成文** |
| 产出 | 人物 perspective 全套 | **精简的 `[作者]-writing-style` Skill** |
| 调研 | 6 Agent 全维度 | **语料驱动的风格维度**（可补充网络） |

---

## Phase 0：入口与语料

### 0.1 必答信息

1. **作者/笔名**（或「匿名，只用语料」）。
2. **语料来源优先级**：默认 **本地优先**；用户声明「仅网络」时再纯检索。
3. **输出路径**：默认 `.cursor/skills/[author-slug]-writing-style/`（slug：小写、连字符）。

### 0.2 本地语料（优先）

- **从 prompt 提取路径**：识别形如路径、`@文件`、`./`、`D:\`、`/` 等指向文件或目录的片段；支持 `.md`、`.markdown`、`.pdf`、`.txt`、`.docx`（若环境可读）。
- **未提供路径时**：主动询问：「请给出文件或文件夹路径（可多条）；或确认暂无本地文件，仅用网络检索。」
- **落地**：在目标 Skill 目录创建 `sources/uploads/`，将用户素材**复制或登记路径**（登记时在 `references/corpus-inventory.md` 写明路径与哈希/修改时间，便于审计）。

### 0.3 网络补充（可选）

- 用于补足：**覆盖面**（体裁单一时的对照样本）、**时效语料**。
- **黑名单与优先级**：继承女娲惯例——不用知乎、微信公众号、百度百科作来源；优先本人博客、书籍节选、权威媒体专访、出版社节选。
- 爬取/摘录存入 `sources/web-clippings/`，每条标注 URL 与抓取日期。

### 0.4 工具

- **PDF**：优先项目已安装的 `pdf` skill 或 `pdfplumber`/`pypdf` 读正文。
- **长网页**：若有 `web-article-reader` 等 skill，对 URL 拉全文再入库。
- 读完的内容写入调研笔记，不依赖「记得对话里的粘贴」。

## Phase 1：语料整理与分层

1. **按体裁打标签**：随笔 / 技术 / 讲故事 / 社交媒体 / 书信 / 译作（若为翻译则降权或单列）。
2. **字数门槛**：单体裁建议合计 ≥ 3000 汉字或等价英文词数再蒸馏；不足则在产出 Skill 的「诚实边界」中标明**样本不足**。
3. **输出**：`references/corpus-inventory.md`——文件列表、体裁、字数估计、是否一手。

---

## Phase 2：风格蒸馏（核心）

从语料中归纳**可操作的写作规则**（要能指导生成，不是泛泛形容词）。

### 2.1 维度清单（必覆盖）

| 维度 | 提取什么 |
|------|----------|
| 句式 | 长短句比例、口语化程度、破折号/括号习惯、问句频率 |
| 词汇 | 高频词、比喻来源域、英文穿插、自嘲/夸张用语 |
| 节奏 | 开篇习惯（金句/场景/定义）、段落长度、转折连接词 |
| 修辞 | 隐喻密度、排比、反讽、列举方式 |
| 叙事视角 | 第一/二人称、是否说教、读者称呼 |
| 标点与排版 | 引号、分段癖好、列表偏好 |

### 2.2 证据原则

- 每条规则尽量附带 **1 句简短引用或改写锚点**（写入 `references/style-anchors.md`，避免超长引用）。
- 区分 **稳定习惯** vs **单篇特例**；后者标注「偶发」。

### 2.3 反模式

- 该作者**明确避免的写法**或从你样本中归纳的「写了就不像 Ta」——列出 3–7 条。

---

## Phase 3：生成「作者写作 Skill」

在 `[输出目录]/SKILL.md` 写入**可被 Cursor 加载**的技能文件，建议结构：

```markdown
---
name: [author-slug]-writing-style
description: |
  模仿 [作者名] 的写作风格与表达方式进行中文/英文辅助写作与改写。
  触发词：「用XX的文风」「像XX那样写」「XX写作style」「切换到XX文风」。
---

# [作者名] · 写作声线

## 何时启用
（短文消息 / 深度文 / 技术科普——根据样本写明）

## 声音速写（50–100 字）
用 Ta 的口吻写自我介绍式段落（虚构也可，但要贴合风格）

## 写作规则（执行级）
（分点列出 Phase 2 的规则）

## 句式与招牌短语
（可选：例句级模板 5–15 条）

## 反模式（不要这样写）
（Phase 2.3）

## 辅助写作工作流
1. 用户给出主题与体裁 → 先列提纲 → 再扩写成文
2. 改写：用户提供草稿 → 按本 Skill 调整句式与节奏，不单换词
3. 不确定处标注「待核对」，不捏造该作者未涉及的专有事实

## 诚实边界
- 样本截止时间、样本体裁偏差
- 无法复刻其学识深度，仅能模仿表达表层
- 引用名言需用户自行核实

## 版本
- v1.0 日期 · 语料摘要（见 references/corpus-inventory.md）
```

**元数据 `description` 必须第三人称**，且包含触发场景（参见 Cursor create-skill 规范）。

## Phase 4：用户如何用产出 Skill 写文章

指导用户（或在同一会话中直接扮演）：

1. **新建对话或 @ 引用** `[author-slug]-writing-style/SKILL.md`。
2. **输入**：主题 + 体裁 + 长度 + 面向读者；可选已有草稿。
3. **输出**：先提纲后正文，或逐段改写；保持作者节奏而非堆砌形容词。
4. **事实核查**：风格 Skill 不负责真实性；涉及数据、引语请用户复核。

---

## Phase 5：持续迭代优化

在产出目录维护 `references/changelog.md`：

| 版本 | 日期 | 变更 | 新增/删除语料 |
|------|------|------|----------------|
| v1.1 | … | 加强短句节奏说明 | 新增 newsletter 两篇 |

**迭代触发**：用户追加 PDF/MD、指出「这句不像」、或文体扩展（如从技术文扩展到随笔）。

**迭代流程**：

1. 新语料放入 `sources/uploads/` 并更新 `corpus-inventory.md`。
2. 仅 Diff **受影响维度**（不必全文重写 SKILL.md）。
3. `changelog.md` 记录；SKILL.md 顶部或底部更新版本号与日期。
4. 若旧规则与新语料冲突：在「内在张力」简短说明并存档两条并存规则（标明语境）。

---

## Phase 1.5 / 2.5 检查点（建议）

- **语料表**：用户确认路径与体裁标签无误。
- **蒸馏摘要**：展示 5–10 条核心风格结论后再写 SKILL.md；用户可纠偏。

---

## 质量底线

- 语料过少时：**缩小声称范围**（例如「仅适用于 Ta 2020 年后的技术博客」），勿编造伪.quote。
- Skill **自包含**：所有 references 与 sources 索引均在 `[author-slug]-writing-style/` 内，便于复制分享。
